## 유효하지 않은 지적과 반박 근거

- **#6 중복 ID**: `list`/`show`는 SPEC·DECISIONS 상 명시적으로 best-effort read-only 조회이며
  참조 무결성(유일성 포함)은 `validate` 가 전담한다 (SPEC §5, D-3). 참조 구현 `show.mjs`
  의 `findTaskById` 도 `.find()` 로 첫 매치를 반환하며 중복을 검사하지 않는다. 데이터를
  변경하지 않고 쓰기 경로의 유일성 검증을 우회하지도 않으므로 Critical 아님. 재검토 2/3
  에서 검토자도 "defensible, not Critical" 로 동의.

## 미해결 · 남은 위험

- #6은 설계상 의도된 동작으로 유지. 사용자가 조회 시 중복 경고를 원하면 별도 개선 항목.
- BOM 이 있는 UTF-8 파일은 `DocumentParseError` (exit 1) 로 거부된다 — 참조(`readFile('utf8')`
  + `JSON.parse`)와 동일 동작이므로 Phase 2 범위에서 변경하지 않음. 필요 시 별도 논의.
- Phase 2는 필수 통과 Phase 아님. 미해결 Critical 없음 → Phase 3 진행 가능.
